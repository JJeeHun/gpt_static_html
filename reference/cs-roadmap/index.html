4. 실제 공부 규칙

우선순위가 자주 바뀌는 환경을 전제로 한 사용 규칙입니다.

① 목표부터 고른다Docker 프로젝트면 Docker 렌즈를 선택하고 P0만 먼저 본다.
② 최소 학습부터“하나만 봐도 됨”이면 핵심 과목 하나로 출발하고, 막힐 때 확장한다.
③ 연결 필수형은 순서 준수예: Socket → I/O Multiplexing → epoll 순서를 건너뛰지 않는다.
④ A를 먼저 닫는다실무 설명과 장애 추적이 가능한 수준까지 A를 우선 완성한다.
⑤ B는 필요할 때 내려간다Kernel/Native 관심이 생기면 같은 노드의 B Deep Dive를 이어서 본다.
⑥ 반드시 관찰한다/proc, strace, ss, vmstat, iostat, perf 등으로 개념이 실제 시스템에서 어떻게 보이는지 확인한다.

문서 목적: “모든 CS를 순서대로 끝내기”가 아니라, 현재 기술 문제에서 필요한 기반 지식으로 빠르게 내려가고 다시 현업 기술로 올라오는 능력을 만드는 것.
